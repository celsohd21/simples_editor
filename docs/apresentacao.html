1. O Problema

"Tenho que compilar e executar um programa SIMPLES. Como eu faço?"

❌ Antes (Fluxo Manual)

  • Instalar Linux 32-bit (VM/WSL)
  • Compilar com simplesc
  • Montar com nasm -f elf32
  • Linkar com ld (i686)
  • Executar binário localmente
  • Zero suporte a leia (stdin)

😖 Atrito

  • Setup complexo para cada aluno
  • Ambiente diferente por SO
  • Sem feedback visual imediato
  • Dificuldade de diagnosticar erros
  • Baixa adesão à prática

Objetivo: Zero instalação local. Tudo no browser.

2. A Solução

Um Web IDE completo com 3 painéis simultâneos

📝 Editor SIMPLES

Monaco Editor com syntax highlighting para 27 keywords, snippets, tema dark

⚙️ NASM Panel

Assembly x86 gerado lado a lado com o código fonte original

💻 Terminal

xterm.js interativo com suporte a leia (stdin) via WebSocket

5. Principais Desafios

🧩 x86 32-bit em ARM64 (Oracle Ampere A1)

O compilador gera código x86 32-bit, mas o deploy é ARM64. Solução: qemu-user-static para emular as instruções dentro do sandbox Docker.

🔌 I/O interativo via WebSocket + PTY

leia precisa de stdin bidirecional em tempo real. Solução: WebSocket com flask-sock + duas tasks asyncio (pty_to_ws / ws_to_pty).

🛡️ Sandbox multi-camadas

Código de aluno pode ser malicioso (fork bomb, socket, exaustão de memória). Solução: 9 layers de segurança — cap_drop, network=none, read-only, cgroups, seccomp, no-new-privs, pids-limit, nobody user, tmpfs.

⏱️ Timeout em 3 camadas

Loop infinito poderia travar o servidor. Solução: timeout de compilação (15s) + timeout de execução (10s) + Docker stop-timeout (12s). SIGTERM → 1s → SIGKILL.

🔄 Pipeline cross-platform

simplesc gera NASM x86, mas o host pode ser x86_64 ou ARM64. Solução: NASM é cross-assembler; binutils-i686-linux-gnu para linkagem cruzada; qemu para execução.

7. Lições Aprendidas

🌐 Frontend

  • Monaco Monarch tokenizer é poderoso para DSLs educacionais
  • react-resizable-panels simplifica layouts complexos
  • xterm.js + WebSocket é a melhor combinação para terminal no browser
  • Playwright E2E tests pegam regressões de UI invisíveis

⚙️ Backend

  • WebSocket sobre REST para I/O interativo foi esencial
  • Strategy Pattern (execução local vs Docker) simplificou dev/prod
  • structlog JSON pago dividendos no diagnóstico de incidentes
  • Rate limiting é crítico em ambiente compartilhado (sala de aula)

🛠️ DevOps

  • Segurança precisa ser defense-in-depth (9 camadas)
  • Cross-platform (x86 → ARM64) exige planejamento desde o início
  • OCI Ampere A1 Always Free é viável para uso acadêmico
  • Ubuntu 22.04 no OCI tem iptables bloqueando portas 80/443 por padrão

📚 Gerais

  • Terraform para infraestrutura reproduzível desde o início
  • qemu-user-static adiciona 5-10x overhead — aceitável para programas didáticos
  • Documentação de incidentes (INCIDENTS.md) reduz tempo de resposta
  • Testes de segurança automatizados (security_tests.py) validam o sandbox
